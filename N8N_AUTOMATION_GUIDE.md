# BRÜNEL ERP — n8n Automation & Telegram Bot Integration Guide
## Deferred Implementation Specification for Module 6 (Accounting), Module 1 (HR Payslips), and Module 3 (Inventory Alerts)

> **Purpose:** This instruction guide explains how to connect **n8n** and the **Telegram Bot API** to the Brünel ERP & Field Operations Platform (`app.bruenel.de` & `portal.bruenel.de`) whenever you are ready to activate background automation.
> All required database columns (`n8n_sync_status`, `drive_file_id`, `storage_key`) and REST API endpoints are already built and active in the backend.

---

## 1. Service Account Authentication Setup

1. Log into `app.bruenel.de` as **Owner / Super Admin** (`sam.rastegar@bruenel.de`).
2. Navigate to **Users & Access Matrix** (`/users`).
3. Create a dedicated Service Account for n8n:
   * **Email:** `n8n-bot@bruenel.de`
   * **Role:** `HR & Finance Admin (Tier 3)` (or `System Bot`)
   * **Granted Modules:** `mod_accounting`, `mod_hr`, `mod_inventory`
4. In **n8n**, create an **HTTP Header Auth** credential or a scheduled token refresh node calling:
   * **Endpoint:** `POST https://api.bruenel.de/api/v1/auth/login` (or `http://localhost:8000/api/v1/auth/login`)
   * **Form Data:** `username=n8n-bot@bruenel.de`, `password=<bot-password>`
   * Store `access_token` and pass `Authorization: Bearer <access_token>` on all subsequent n8n HTTP Request nodes.

## 2. Workflow 1: Approved Expense Compilation & Google Drive Archiving

### Trigger / Schedule
* Run every **15 minutes** (Cron node in n8n) or trigger via webhook when an expense is approved in `app.bruenel.de`.

### Step-by-Step n8n Nodes
1. **HTTP Request Node (Fetch Approved Expenses):**
   * `GET /api/v1/accounting/expenses?status=Approved`
   * Filter records where `n8n_sync_status == "Queued_For_DATEV_Export"`.
2. **HTTP Request Node (Download Receipt Media from S3):**
   * For each expense with a `receipt_url`, download the receipt binary using `GET <receipt_url>`.
3. **Google Drive Node (Archive Receipt & Compiled PDF):**
   * Authenticate using a **Google Cloud Service Account** (restricted to the Brünel Accounting Shared Drive).
   * Upload the receipt file into `/Brünel_Buchhaltung/2026/<Period_Month>/<Category>/`.
   * Capture the returned Google Drive `fileId`.
4. **DATEV / Lexware Export Node:**
   * Fetch the structured CSV directly from `GET /api/v1/accounting/export-datev` and forward it to your accounting mailbox or DATEV Unternehmen Online API.

## 3. Workflow 2: Automated Monthly Payslip (`Lohnabrechnung`) Distribution

### Goal
Automatically ingest monthly payroll PDFs generated by your tax advisor (`Steuerberater` / DATEV) from a secure Google Drive folder and publish them into each employee's private vault on `portal.bruenel.de`.

### Step-by-Step n8n Nodes
1. **Google Drive Trigger Node:**
   * Watch folder `/Brünel_HR_Lohnabrechnungen/Incoming_PDFs/`.
   * Expected filename convention: `BRN-1005_2026_10_Lohnabrechnung.pdf` (starts with `employee_number`).
2. **HTTP Request Node (Match Employee & Fetch Monthly Provision):**
   * Call `GET /api/v1/hr/employees` to match `employee_number` (`BRN-1005`) to `employee_id` (`UUID`).
   * Call `GET /api/v1/sales/commissions/<employee_id>` to retrieve the employee's earned Field Sales `total_commission` (`Provision`) for that month.
3. **HTTP Request Node (Upload PDF to Brünel S3 Vault):**
   * Call `POST /api/v1/media/upload` (multipart/form-data):
     * `reference_type`: `Lohnabrechnung`
     * `reference_id`: `<employee_id>`
     * `employee_id`: `<employee_id>`
     * `title`: `Lohnabrechnung 10/2026`
     * `file`: `<PDF binary>`
   * Capture `id` as `document_id`.
4. **HTTP Request Node (Issue Payslip Record to Employee Portal):**
   * Call `POST /api/v1/hr/payslips`:
     ```json
     {
       "employee_id": "<employee_id>",
       "period_month": 10,
       "period_year": 2026,
       "gross_salary": 3600.00,
       "net_salary": 2450.00,
       "commission_bonus": 125.00,
       "hours_worked": 168.0,
       "document_id": "<document_id>",
       "notes": "Auto-imported via n8n Payroll Pipeline"
     }
     ```

## 4. Workflow 3: DSGVO-Compliant Telegram Operational Alerts

> **Important DSGVO / GDPR Rule (Chapter 2.1 & 5.6):** Never transmit employee names, salaries, sickness reasons, or personal data over Telegram. Only send non-sensitive operational SKU/Stock/Object status alerts.

### Step-by-Step n8n Nodes
1. **Cron Node (Every Hour):**
   * Call `GET /api/v1/inventory/stock`
2. **IF Node (Filter Low Stock):**
   * Filter items where `low_stock_alert == true`.
3. **Telegram Bot Node (`sendMessage`):**
   * Format message strictly with non-personal operational identifiers:
     ```text
     ⚠️ BRÜNEL LAGER ALERT
     SKU: {{ $json.sku }} ({{ $json.material_name }})
     Location: {{ $json.lager_type }} - {{ $json.lager_name }}
     Current Stock: {{ $json.current_stock }} {{ $json.unit }} (Min: {{ $json.min_stock_threshold }})
     ```
